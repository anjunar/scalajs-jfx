03 / Architekturentscheidungen

Eine andere Abwägung

Entscheidend ist, welche Architektur zu deiner Anwendung passt. JFX verbindet eine Scala.js-Implementierung, explizite Properties und Anwendungskomponenten mit APIs für Scala und TypeScript.

Diese Gegenüberstellung beschreibt Architekturentscheidungen, keine Rangliste von Funktionen. Die verlinkte offizielle Dokumentation erläutert die Alternativen. JFX wird aktiv entwickelt: Prüfe API-Abdeckung und Ökosystem anhand deiner Projektanforderungen. Es richtet sich an Entwickler, die eine explizite, typisierte Runtime für Anwendungen in Scala und TypeScript suchen.

src/main/scala/Counter.scala · Scala
import jfx.core.component.{AbstractComponent, Runtime}
import jfx.core.dsl.EventDsl.onClick
import jfx.core.dsl.DslLayer.render
import jfx.core.layout.Button.button
import jfx.core.layout.TextComponent.text
import jfx.core.layout.VBox.vbox
import jfx.core.render.{Cursor, DomCursor}
import jfx.core.state.Property
import org.scalajs.dom

final class Counter extends AbstractComponent {
  val tagName = "main"

  override def compose(cursor: Cursor): Unit = {
    render(this, cursor) {
      val count = Property(0)

      vbox {
        text(count.map(n => s"Count: $n")) {}
        button("Increment") {
          onClick(_ => count.set(count.get + 1))
        }
      }
    }
  }
}

object Main {
  def main(args: Array[String]): Unit =
    Runtime.mount(new Counter, DomCursor.root(dom.document.getElementById("root")))
}

05 / Unter den APIs

Zwei Zugänge.
Eine Implementierung.

Scala setzt JFX-Komponenten direkt zusammen. Die TypeScript-Fassade ruft die Scala.js-Bridge auf. Beide nutzen dieselbe Implementierung für Rendering, Zustand und Komponenten.

Gemeinsame Fähigkeiten bedeuten keine identischen API-Oberflächen. Beispielsweise stellt die TypeScript-Fassade nicht jeden imperativen Scala-Komponentenzugriff bereit.

07 / Die Überlegung dahinter

Warum es JFX gibt

JFX untersucht eine einfache Idee: Der Komponentenbaum kann die gemeinsame Grundlage für Server-Rendering, Browser-Interaktion und Anwendungssteuerelemente sein.

Das Projekt bringt einen auf Properties basierenden, kombinierbaren Ansatz nach Scala.js und macht dieselbe Implementierung für TypeScript verfügbar. Expliziter Zustand, klar verwaltete Lebenszyklen und nutzbares Server-HTML bestimmen die Gestaltung. Den technischen Überblick lesen ↗.
