Die Grundlagen

Was Scala JS UI 1.0 mitbringt

01

Server-Rendering

Erzeuge HTML auf dem Server und hydriere dasselbe Komponentenmodell anschließend im Browser.

02

Expliziter reaktiver Zustand

Properties lesen, setzen und ableiten. Zustandsänderungen werden synchron weitergegeben; Komponenten verwalten die Lebensdauer ihrer Abonnements.

03

Anwendungskomponenten

Kombiniere typisierte Formulare, Tabellen, virtualisierte Sammlungen, Layouts und einen Editor mit Markdown als Datenformat.

04

Scala + TypeScript

Wähle eine der beiden APIs. Rendering, Zustand und Komponentenverhalten stammen aus derselben Scala.js-Runtime.

05

Internationalisierung am Quelltext

Ausgangstexte und Interpolation bleiben beim Code; Kataloge enthalten die Übersetzungen.

06

Schrittweise Erweiterung

Liefere zuerst lesbare Inhalte und gewöhnliche Links. Hydration ergänzt Bearbeitung und umfangreichere Interaktion.

src/main/scala/Counter.scala · Scala
import ui.core.component.{AbstractComponent, Runtime}
import ui.core.dsl.EventDsl.onClick
import ui.core.dsl.DslLayer.render
import ui.core.layout.Button.button
import ui.core.layout.TextComponent.text
import ui.core.layout.VBox.vbox
import ui.core.render.{Cursor, DomCursor}
import ui.core.state.Property
import org.scalajs.dom

final class Counter extends AbstractComponent {
  val tagName = "main"

  override def compose(cursor: Cursor): Unit = {
    render(this, cursor) {
      val count = Property(0)

      vbox {
        text(count.map(n => s"Count: $n")) {}
        button("Increment") {
          onClick(_ => count.set(count.get + 1))
        }
      }
    }
  }
}

object Main {
  def main(args: Array[String]): Unit =
    Runtime.mount(new Counter, DomCursor.root(dom.document.getElementById("root")))
}

Unter den APIs

Zwei Zugänge.
Eine Implementierung.

Scala setzt Scala JS UI 1.0-Komponenten direkt zusammen. Die TypeScript-Fassade ruft die Scala.js-Bridge auf. Beide nutzen dieselbe Implementierung für Rendering, Zustand und Komponenten.

Gemeinsame Fähigkeiten bedeuten keine identischen API-Oberflächen. Beispielsweise stellt die TypeScript-Fassade nicht jeden imperativen Scala-Komponentenzugriff bereit.

Die Überlegung dahinter

Warum es Scala JS UI 1.0 gibt

Scala JS UI 1.0 untersucht eine einfache Idee: Der Komponentenbaum kann die gemeinsame Grundlage für Server-Rendering, Browser-Interaktion und Anwendungssteuerelemente sein.

Das Projekt bringt einen auf Properties basierenden, kombinierbaren Ansatz nach Scala.js und macht dieselbe Implementierung für TypeScript verfügbar. Expliziter Zustand, klar verwaltete Lebenszyklen und nutzbares Server-HTML bestimmen die Gestaltung. Den technischen Überblick lesen ↗.
